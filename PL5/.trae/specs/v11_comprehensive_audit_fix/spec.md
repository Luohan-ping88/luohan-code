# PL5 系统全面审计与优化 V11 - 产品需求文档

## 概述
- **摘要**: 对 PL5 V10.3 系统进行全面审计，修复关键问题（进程误杀、特征一致性、日循环流程、启动脚本统一、特征-模型不匹配），并进行端到端部署验证
- **目的**: 解决系统运行中的关键缺陷，确保智能机制和日循环机制的一致性，提升系统稳定性
- **目标用户**: PL5 系统管理员、用户、开发者

## 目标
1. **修复进程误杀问题** - 确保系统重启时只终止属于 PL5 的进程
2. **修复特征组一致性问题** - 确保动态特征选择机制在训练和推理中的一致性
3. **修复日循环流程完整性** - 确保完整的多佐证链执行（10:00,13:00,15:00,16:00,17:00,18:00,19:00,20:00,20:15）
4. **统一启动脚本** - 确保所有启动脚本与当前系统架构一致
5. **修复特征-模型不匹配** - 解决模型期望76个特征但当前只有43个的问题
6. **端到端验证** - 验证所有修复后系统正常运行

## 非目标（范围外）
- 不开发新的预测模型
- 不重构核心预测算法
- 不添加新功能，只修复现有问题

## 背景与上下文
当前系统存在以下关键问题：
1. **进程误杀**: 启动时会误杀非 PL5 进程
2. **特征-模型不匹配**: 模型（pl5_predictor_v8.joblib）期望76个特征，但当前特征工程模块只能提取约43个特征
3. **版本不一致**: 部分地方显示旧版本号
4. **日循环流程**: 需要确认所有佐证步骤是否正确执行
5. **启动脚本**: 多个启动脚本可能过时或不统一

技术约束：
- 需保持 V10.3 版本兼容性
- 使用现有代码库架构
- 优先使用已实现的 process_guardian.py 的精确匹配机制

## 功能需求

### FR-1: 进程管理安全机制优化
- 所有启动脚本使用精确的进程匹配机制（来自 process_guardian.py 的逻辑）
- 添加进程白名单机制，只终止明确属于 PL5 的进程
- 进程识别使用多重验证：Python进程 + PL5标识符 + 路径匹配 + 模块启动模式

### FR-2: 动态特征组一致性保证
- 确保训练和推理使用完全相同的特征提取逻辑
- 验证特征选择机制（RFE/SelectFromModel）的一致性
- 添加特征版本管理检查机制

### FR-3: 日循环多佐证链完整性
- 验证所有11个关键时间点的任务是否正确调度
- 确保预测验证链：首次(10:00) → 二次(13:00) → 三次(15:00) → 深度优化(16:00) → 预生成(17:00) → 最终(18:00) → 验证(19:00) → 售前(20:00) → 发送报告(20:15)

### FR-4: 启动脚本统一与合规
- 统一所有启动脚本（start.bat, start_pl5_reliable.bat, start_daemon.bat, launch_system.py, start_system.py等）
- 确保所有脚本使用相同的进程检查和启动逻辑
- 添加脚本版本检查和兼容性验证

### FR-5: 特征-模型匹配问题解决
- 分析当前特征工程模块与模型期望特征的差异
- 选择方案：重新训练模型 或 恢复缺失特征计算
- 确保预测功能完全正常

## 非功能需求
- **NFR-1: 可靠性**: 系统启动后24小时内无崩溃
- **NFR-2: 性能**: API响应时间 < 2秒
- **NFR-3: 可维护性**: 修复后的代码易于理解和维护

## 约束
- **技术**: Python 3.12, FastAPI, joblib
- **业务**: 必须在当前数据和模型基础上修复，不影响现有功能
- **依赖**: 依赖现有 process_guardian.py、auto_scheduler_v8.py 等模块

## 假设
1. process_guardian.py 中的精确匹配机制是正确的
2. 现有特征工程代码是最新的（engineer.py）
3. 训练和推理环境一致

## 接受标准

### AC-1: 进程误杀问题修复
- **给定**: 系统中有其他Python进程在运行
- **当**: 执行启动脚本或 stop_service.bat
- **则**: 只终止属于 PL5 的进程，其他进程完全不受影响
- **验证**: programmatic + manual check
- **备注**: 使用 process_guardian.py 的 get_all_pl5_processes() 进行验证

### AC-2: 特征-模型匹配修复
- **给定**: 系统已加载预测模型
- **当**: 调用预测API (/api/pl5/prediction)
- **则**: 预测成功返回，不出现 "X has N features, but model expects M" 错误
- **验证**: programmatic test

### AC-3: 日循环流程完整性
- **给定**: 调度器正在运行
- **当**: 查看调度任务列表
- **则**: 所有11个关键时间点的任务都已注册且状态正常
- **验证**: programmatic check + human verification

### AC-4: 所有启动脚本一致
- **给定**: 系统中有多个启动脚本
- **当**: 对比各启动脚本
- **则**: 使用相同的进程检查逻辑、Python路径、启动参数
- **验证**: code review + manual test

### AC-5: 端到端系统正常运行
- **给定**: 所有修复完成
- **当**: 运行完整的端到端测试
- **则**: 所有测试通过，系统稳定运行
- **验证**: e2e test
