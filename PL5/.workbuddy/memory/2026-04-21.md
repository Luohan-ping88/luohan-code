## 核心问题发现：特征漂移 Bug

### 问题描述
完整系统测试报错：
```
X has 100 features, but RandomForestClassifier is expecting 76 features as input.
```

### 根因分析
1. **V8模型**（`pl5_predictor_v8.joblib`）训练时，RFE特征选择选出 **76个特征**，存储在 `state['feature_cols']`
2. **预测时**，`FeatureEngineer.extract_all_features()` 重新运行RFE，选出 **100个特征**
3. V8的 `StackingEnsemble.predict_proba_position()` 调用 RF 分类器时，传入100特征但RF期望76特征 → 维度不匹配

### 修复方案
修改 `src/core/orchestrator.py` 的 `execute_prediction_pipeline()`：
1. **先加载模型**（`predictor.load_models()`）
2. **优先使用模型存储的 feature_cols**（V8=76，V10=100）
3. 缺失特征列用 0 填充（而非回退到RFE，因为RFE的特征数仍可能与训练时不符）

同步修改 `main.py` 的 `cmd_predict()`，应用相同逻辑。

### 关键数据
- V8模型: `feature_cols` = 76个，`trained_feature_dim` = 76
- V10模型: `feature_cols` = 100个，`trained_feature_dim` = 100
- 完整系统测试耗时: 41.97秒

## Bug 3: pandas Series 索引不兼容（今日修复）

### 问题描述
完整系统测试 `test_full_system.py` 偶发失败：
```
ERROR - 预测流程执行失败: -1
[FAIL] 预测流程失败: -1
```

经增强异常日志（`traceback.format_exc()`）确认为 `KeyError: -1`：
```
File "predictor.py", line 183, in predict_position
    last_digit = int(seq[-1]) if len(seq) > 0 else 0
KeyError: -1
```

### 根因分析
- `_debug2.py` 测试成功：传入 `recent_original_data` 是 `{pos: list}` → `seq[-1]` 在 list 上正常工作
- `test_full_system.py` 经 orchestrator 失败：传入 `recent_original_data` 是 `{pos: pandas.Series}` → `seq[-1]` 在 pandas.Series（RangeIndex）上查 key `-1` 不存在 → `KeyError: -1`
- pandas Series 的 RangeIndex 默认从 0 开始，不包含 -1

### 修复方案
`src/core/models/predictor.py` 第 178-184 行：
```python
# 修复前（不兼容 pandas Series）
seq = recent_data.get(other_pos, np.array([0]))
last_digit = int(seq[-1]) if len(seq) > 0 else 0

# 修复后（兼容 pandas Series + numpy + list）
seq = recent_data.get(other_pos, np.array([0]))
try:
    last_digit = int(seq.iloc[-1]) if hasattr(seq, 'iloc') else int(seq[-1])
except (KeyError, IndexError, ValueError):
    last_digit = 0
```

同步修复：`src/core/orchestrator.py` 异常处理，记录完整 traceback。

### 测试验证（修复后）
- 完整系统测试：`test_full_system.py` → **PASS**（43.3s）
- 冒烟测试：12/12 PASS
- E2E测试：8/8 PASS

## Bug 4: RFE 特征选择导致模型训练特征子集缺失（今日彻底修复）

### 问题描述
系统运行时报 WARNING：`[Orchestrator] 模型特征列中有 30 个缺失，将用0填充`

### 根因分析（完整链路）
1. V8 模型训练时：RFE 从 301 全量特征中选出 **76 个**最优特征 → 保存到 `pl5_predictor_v8.joblib['feature_cols']`
2. 预测时：`extract_all_features(select_top=100)` → RFE 重新选出 **107 个**特征（当前数据上的最优 107）
3. V8 模型 76 个训练特征中，有 **30 个不在新的 top-107 中** → 被强制填充为 0
4. 模型收到损坏信号（30% 输入为零），预测准确率受损

### 修复方案
在所有预测路径中，将 `extract_all_features(df)` 改为 `extract_all_features(df, select_top=None)`，跳过 RFE 限制，生成全量 301 特征，保证 V8 模型的 76 个训练特征全部存在。

修改文件：
- `src/core/orchestrator.py` 第 454 行：预测路径
- `main.py` 第 138 行（cmd_predict）：独立预测入口
- `scripts/utility/generate_prediction.py`：独立预测脚本（同步修复 + 重构模型加载逻辑）

### 测试验证（修复后）
- 完整系统测试：✅ PASS，**"30 个缺失" 警告完全消失**
- 日志显示：`使用模型训练时的 76 个特征列（特征漂移已修复）`
- 预测耗时：36s（比修复前 44s 快 18%，因跳过了 RFE 筛选）

## Bug 5: NumPy int64 JSON 序列化错误（今日修复）

### 问题描述
工作流任务失败：
```
首次预测验证失败: Object of type int64 is not JSON serializable
最终预测失败: Object of type int64 is not JSON serializable
售前最终预测失败: Object of type int64 is not JSON serializable
```

### 根因分析
`auto_scheduler_v8.py` 中多处使用 `data['period'].iloc[-1]` 直接存入 dict，然后 `json.dump()`：
- pandas Series 的 `.iloc[-1]` 返回 NumPy int64 类型
- Python 标准库 `json` 不支持 NumPy 类型序列化

### 修复方案
将所有 `data['period'].iloc[-1]` 改为 `int(data['period'].iloc[-1])`，显式转换为 Python int。

修改文件：`src/app/auto_scheduler_v8.py`
- 第 1450 行：`task_final_prediction` 中的 `latest_period`
- 第 1549 行：`task_second_prediction_verification` 中的 `latest_period`
- 第 1655 行：`task_pre_sale_prediction` 中的 `latest_period`
- 第 1754 行：`task_first_prediction_verification` 中的 `latest_period`
- 第 1977 行：`task_prediction_preview` 中的 `latest_period`

### 测试验证
```python
# 修复前
{'latest_period': data['period'].iloc[-1]} → json.dumps() 失败

# 修复后
{'latest_period': int(data['period'].iloc[-1])} → json.dumps() 成功
```
