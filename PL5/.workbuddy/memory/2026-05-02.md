# 2026-05-02 日循环周期判断修复

## 问题：凌晨补跑已完成的任务
系统重启后，在凌晨 00:00-02:00 期间错误地补跑了15:00三次佐证、16:00深度优化等应该在上一个日循环已完成的任务。

## 根因分析
`check_intelligent_scheduling` 中的周期判断用 `time` 对象做比较，存在**跨天时间回绕**问题：
- 凌晨 01:00 时，`01:00 <= 20:15` 成立（数值上小于），代码认为还在上一个"昨天22:00→今天20:15"的周期内
- 但实际上 01:00 已经过了该周期的结束时间（20:15），属于死区
- 系统于是补跑了所有"未完成"的任务，导致任务乱序执行

## 修复（3处）

### 修复1：周期判断改用完整 datetime 比较
- 原：`elif current_time <= send_report_time:`
- 新：`elif now >= yesterday_22:`（完整datetime比较）
- 三路分支：`now >= today_22`(22:00后) / `now > today_2015`(20:15-22:00死区) / `now >= yesterday_22`(昨天22:00-今天20:15)

### 修复2：cutoff 检查改用完整 datetime 比较
- 原：`if current_time >= cutoff_time:`（time比较，01:00 < 21:00 不触发）
- 新：`if now >= cutoff_datetime:`（datetime比较，确保正确检测）

### 修复3：_execute_catchup_tasks 和 _calculate_task_durations 也改用 datetime
- 传递 cutoff_datetime 而非 cutoff_time
- 负可用时间处理：返回仅含 send_report 的最小任务集
